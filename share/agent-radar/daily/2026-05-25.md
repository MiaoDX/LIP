# Agent Radar Daily — 2026-05-25

> 今日主线：这两天最值得记的，不是 agent 又更会写代码了，而是平台开始主动把**治理面外置**：收窄默认模型面、暴露安全审计 API、把 secrets / network policy 挪到 runtime 之外，并把团队级 sandbox workflow 做成产品。

## 1. 新增事实

- **2026-05-21 — GitHub / Copilot for Eclipse 开源**：GitHub 把 Copilot for Eclipse 以 MIT 协议开源，公开了 chat、agent mode、skills / prompt files、BYOK 和 context handling 的实现细节。意义不在 Eclipse 本身，而在于 agent wiring 开始变得可审查、可复用。  
  https://github.blog/changelog/2026-05-21-github-copilot-for-eclipse-is-open-source

- **2026-05-20 — GitHub / Copilot Web 收窄模型面**：Copilot Chat on Web 移除了全部 Gemini 模型，以及部分 OpenAI 模型（包括 GPT-5.2 Codex、GPT-5.4 nano），理由是提升一致性和质量。这说明 agent 产品开始主动做 capability surface reduction。  
  https://github.blog/changelog/2026-05-20-updates-to-available-models-in-copilot-on-web

- **2026-05-21 — LangChain / LangSmith Auth Proxy**：LangChain 发布 Auth Proxy，把认证头注入放到网络层，而不是把长寿命密钥直接交给 sandbox；同时支持 egress policy 和动态 credential flow。这比再加一层 prompt guard 更像 production 控制面。  
  https://www.langchain.com/blog/how-auth-proxy-secures-network-access-for-langsmith-agent-sandboxes

## 5. 对 MiaoDX 的复用价值

- 可以立一篇 `Agent Control Plane Outside the Runtime`：把 Auth Proxy、egress policy、scoped credentials、审计 API 放在同一篇里。
- 可以立一篇 `Capability Surface Reduction`：为什么成熟产品会主动减少默认模型面，而不是无限开放。
- `LIP / OPC` 可以补一个 checklist：
  - secrets 是否留在 runtime 外？
  - repo / session 的 tools、MCP、firewall、workflow policy 是否可审计？
  - 团队能否在同一 sandbox 上做人机接力，而不是一次性跑完？
