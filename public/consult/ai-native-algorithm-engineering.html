02 / Evidence

两个已经公开的机器人 Agent 案例

Case A · Roboharness

从真实机器人项目抽出来的 Agent 验收层

真实项目中，agent 能改代码、调参数、跑仿真，但长程任务会卡在“它不知道自己改完后是否真的变好”。Roboharness 把验收做成 metric + visual 的双轨证据流水线，让 agent 每轮都有 PASS / FAIL / surface-to-human 的判断依据。

  • 机器人抓取规划从 16 秒优化到约 3 秒
  • 视觉发现 unknown unknown，再沉淀成稳定 metric
  • artifact / report 让人不用每轮盯屏验收
完整 HTML report GitHub repo
Case B · RoboClaws

给机器人开放任务一个可维护的大脑

给机器人接一个大模型不等于拥有智能。RoboClaws 把开放任务组织成 task / skill / MCP tool / backend / report 的边界，让机器人任务能运行、能失败、能留下证据、能被下一轮改进。

  • Skill 承载策略经验，MCP 保持稳定能力边界
  • runtime map 和 report 保存 agent 的世界记忆
  • 同一套 contract 可迁移到仿真和真机方向

03 / Team Fit

我能为硬件 AI / 算法工程架构团队承担的 scope

Scope 01

算法实验与评测 Agent Loop

把内部计算、数据、训练、仿真和评测平台封装成 agent 可调用的稳定能力，让 research idea 能自动开任务、跑 baseline、收集指标、生成报告。

Scope 02

跨模块 Pipeline 可观测性

用工程视角拆解 pipeline 的延迟、资源、quota、退化和责任边界，让多个算法模块在同一产品目标下优化。

Scope 03

仿真到产品的证据协议

把 demo、仿真、真机 pilot、human review 统一成可审计证据，避免“看起来成功”的假阳性进入长期迭代。

Scope 04

团队级 AI Coding Workflow

帮助团队建立计划、对齐、实现、review、降熵和文档分层机制，让 AI coding 从个人习惯变成可复制的工程制度。

04 / Conversation

下一轮沟通我会主动对齐的几个问题

Question 01

这个团队最终 owner 哪类指标

用户体验、算法效果、pipeline 性能、交付稳定性，还是研发迭代效率？不同答案对应不同架构抓手。

Question 02

算法团队和工程架构团队的边界如何定义

当 A/B 两个团队都能做一件事时，谁负责规则、quota、验收、回归和长期维护？

Question 03

内部是否已经有统一仿真 / 评测 / 数据平台

如果已有，我可以把它们封装给 agent；如果没有，我会先从最小闭环建立 report 和 metric 协议。

Question 04

AI agent 是个人效率工具，还是准备进入研发基础设施

如果目标是后者，需要的不只是 prompt，而是权限边界、工具封装、证据格式、回归机制和团队共识。
