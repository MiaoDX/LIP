适合切入的工程问题

  • 算法工程架构需要连接算法团队、OS、端侧资源和产品准出
  • 仿真、评测、数据、训练和内部平台需要被 agent 安全调用
  • 跨模块 pipeline 需要资源预算、性能画像、回归和准出机制
  • AI coding 需要从个人提效走向团队级研发基础设施
01 / Positioning

不是“会用 Codex”
而是把算法工程系统改成 AI-native

我关心的是：怎样让算法、端侧资源、仿真、评测、证据和工程交付进入同一个 agent 可运行闭环
System

从单点算法到系统交付

自动驾驶感知系统和机器人应用栈经验，让我更关注接口、资源约束、延迟、可观测性、版本准出和产品化边界。

Harness

从人工盯屏到自我验收

把人脑里的验收判断拆成 metric、visual evidence、日志、artifact 和 report，让 agent 可以连续跑。

Cadence

从单点 SOTA 到节奏管理

小团队更适合用稳定的评测节奏跟进业界最佳实践，在阶段目标达成后切换到下一个瓶颈。

02 / Evidence

端侧系统工程 + 两个公开机器人 Agent 案例

Case 0 · Perception System

自动驾驶感知系统：把多模块算法交付到有限端侧资源

在感知系统团队，我负责的不是单个算法效果，而是让多个感知模块在有限端侧资源里稳定完成部署、集成、发版和准出：模型部署框架、资源预算、性能画像、端侧数据通路优化，以及跨模块质量收口。

  • 用全局视角拆解 pipeline 延迟、资源占用和模块责任边界
  • 提供部署、性能分析和准出工具，让算法团队在 contract 内迭代
  • 关注产品交付质量，而不是替算法团队抢单点模型效果归属
Case A · Roboharness

从真实机器人项目抽出来的 Agent 验收层

真实项目中，agent 能改代码、调参数、跑仿真，但长程任务会卡在“它不知道自己改完后是否真的变好”。Roboharness 把验收做成 metric + visual 的双轨证据流水线，让 agent 每轮都有 PASS / FAIL / surface-to-human 的判断依据。

  • 机器人抓取规划从 16 秒优化到约 3 秒
  • 视觉发现 unknown unknown，再沉淀成稳定 metric
  • artifact / report 让人不用每轮盯屏验收
完整 HTML report GitHub repo
Case B · RoboClaws

给机器人开放任务一个可维护的大脑

给机器人接一个大模型不等于拥有智能。RoboClaws 把开放任务组织成 task / skill / MCP tool / backend / report 的边界，让机器人任务能运行、能失败、能留下证据、能被下一轮改进。

  • Skill 承载策略经验，MCP 保持稳定能力边界
  • runtime map 和 report 保存任务状态、运行轨迹和待处理对象
  • 同一套 contract 可迁移到仿真和真机方向

Design Choice

MCP 是能力边界，Agent SDK / Codex / Claude Code 是不同层级 harness

我不会默认自研 planner。当前开放任务复杂度下，通用 agent 已经能把自然语言目标拆成动作阶段，工程重点更应该放在 MCP 能力边界、可观测性、失败恢复、评测指标和 evidence report 上。

03 / Team Fit

和硬件 AI / 算法工程架构团队的连接点

Scope 01

端侧算法系统工程

连接算法、OS、硬件资源和交付准出：模型部署框架、资源预算、性能画像、版本质量和跨模块收口。

Scope 02

算法实验与评测 Agent Loop

把内部计算、数据、训练、仿真和评测平台封装成 agent 可调用的稳定能力，让 research idea 能自动开任务、跑对照实验、收集指标、生成报告。

Scope 03

跨模块 Pipeline 可观测性

用工程视角拆解 pipeline 的延迟、资源预算、退化和责任边界，让多个算法模块在同一产品目标下优化。

Scope 04

仿真到产品的证据协议

把 demo、仿真、真机 pilot、human review 统一成可审计证据，避免“看起来成功”的假阳性进入长期迭代。

Scope 05

算法团队协作 Contract

更倾向提供评测基准、性能画像、工具和验收协议；只有在性能约束明确时，才一起讨论模型部署方案调整，而不是默认抢单点模型效果归属。

Scope 06

团队级 AI Coding Workflow

共建计划、对齐、实现、review、降熵和文档分层机制，让 AI coding 从个人习惯变成可复制的工程制度。

04 / Discussion Anchors

适合进一步展开的技术议题

Anchor 01

全局资源预算和准出权怎样落地

端侧产品需要有人把用户体验、算法效果、pipeline 延迟、资源占用和发版风险组织进同一套全局约束。

Anchor 02

模型部署方案的协作边界

工程架构团队可以提供工具、性能画像和候选建议；真正挑战既有算法方案时，需要明确质量、归属和团队协作成本。

Anchor 03

开放任务如何做 eval

语义地图准确性、任务耗时、推理耗时、工具调用次数、环境交互次数和任务完成比例，都可以进入同一套 report。

Anchor 04

平台能力如何被 agent 安全调用

仿真、评测、数据、训练和内部工具需要明确权限、输入输出、资源边界、失败路径和 report 格式，才能进入长程自动化。

Anchor 05

主模型选择如何平衡产品红线和端侧约束

自研模型、候选开源模型、端侧尺寸、延迟、成本和合规红线，需要在业务 team 和模型 team 之间形成可讨论的决策面。

Anchor 06

AI coding 如何进入研发基础设施

从个人 prompt 到团队工作流，需要权限边界、工具封装、证据格式、回归机制和共识沉淀一起演进。
