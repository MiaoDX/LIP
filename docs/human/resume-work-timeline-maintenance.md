# Resume 与 Work Timeline 维护规范

本文档定义 Resume、Work Timeline、配套讲稿和面试材料的长期维护方式。目标不是让所有材料使用相同版式，而是让它们基于同一组事实、采用一致的叙事语义，并针对不同读者保留合适的信息密度。

## 核心原则

1. **一个事实基础，多种阅读表面**：任职、职责、项目、指标和贡献边界只维护一套可信事实，再按公开简历、演示、口述和定向岗位讨论分别提炼。
2. **统一语义，不统一版式**：所有主要经历都能回答 `WHY → MY SCOPE → WHAT CHANGED → EVIDENCE → CARRY FORWARD`，但不要求每份材料逐项展示这五个标签。
3. **证据优先于形容词**：优先说明负责范围、改变的系统和可复查结果，少用“丰富经验”“深度参与”“能力突出”等无法验证的表达。
4. **公开边界先于表达完整性**：公开材料宁可少讲，也不使用未经确认的内部名称、链接、人员、绩效、版本号、客户信息或指标。
5. **准确归因**：严格区分“负责”“提出并主导”“推动”“参与”和“团队共建”，不把团队或平台结果写成个人独立成果。

## 叙事骨架

| 层次 | 要回答的问题 | 常见内容 |
| --- | --- | --- |
| `WHY` | 为什么这件事值得做 | 新业务阶段、系统瓶颈、交付风险、角色变化 |
| `MY SCOPE` | 我实际负责什么 | 决策边界、团队规模、横向/纵向职责、明确非职责 |
| `WHAT CHANGED` | 我改变了什么 | 架构、流程、工具、评测、团队分工或技术判断 |
| `EVIDENCE` | 如何证明产生了结果 | 指标、交付、覆盖范围、持续运行情况、奖项或公开案例 |
| `CARRY FORWARD` | 这段经历如何影响下一阶段 | 可迁移方法、责任扩大、后续仍在运行的机制 |

这套骨架是内容检查工具，不是固定写作模板。Resume 通常压缩为 `范围 + 动作 + 证据`；Work Timeline 才展开完整因果和能力迁移；面试追问时可进一步使用 STAR 或 CAR 讲具体案例。

## 材料职责

| 材料 | 当前 source of truth | 读者与组织方式 |
| --- | --- | --- |
| 私有事实档案 | `interviews/external_interviews/_common/performance-history.md` | 按时间保存来源、背景、原始口径和细节；不是对外简历 |
| Resume 内容 | `sites/miaodx.com/resume/resume-data.js` | 招聘者快速扫读；定位、四条代表证据、倒序经历 |
| Resume 网页与 PDF | `sites/miaodx.com/resume/index.html`、`print.html` 和版本化 PDF | 由同一数据源生成；PDF 是派生产物，不手工改文案 |
| Work Timeline | `presentations/work-timeline.html` | 公开职业弧线、阶段因果、代表案例和方法总结 |
| 公开讲稿 | `share/work-timeline-script.md` | 面向公开分享的自然口述，不逐字重复页面 |
| 私有面试讲稿 | `interviews/external_interviews/_common/work-timeline-speaking-script.md` | 在公开主线之上增加时间控制、敏感边界和岗位讨论接法 |
| 公司 brief | `interviews/external_interviews/<company-slug>/brief.md` | 只保存岗位匹配、差异、案例选择和反向问题；引用通用材料，不复制完整履历 |

公开项目的能力与指标还应回到对应公开仓库或可复查产物验证。私有事实档案不是所有公开项目的唯一证据来源。

## Resume 组织规则

Resume 使用金字塔式、证据优先的结构：

1. 摘要用两到三句话回答“是谁、最可信的代表经历、现在聚焦什么”
2. 工作主线默认保留四条，每条采用“能力领域 + 代表证据”，避免与摘要重复
3. 主要工作阶段保留三到五条 bullet，优先使用“范围/主题：动作 + 结果”
4. 最近和最相关的经历写得更完整，早期经历逐步压缩
5. 每个数字同时检查范围、时间、统计口径和可公开性
6. 项目、分享、教育和关键词只补充工作经历没有回答的信息

Resume 不承担完整背景说明。一个 bullet 如果必须读完三层背景才能理解，应把背景移到 Work Timeline 或面试案例中，只在 Resume 保留结论和证据。

## Work Timeline 组织规则

Work Timeline 使用“职业弧线 + 可独立讨论的阶段案例”：

1. 首页给出长期定位和责任演进
2. 第二页建立全景因果图，并明确统一阅读顺序
3. 后续每页聚焦一个阶段问题或代表案例，能够被单独跳转和讨论
4. 页面保留不同视觉结构，但语义上都能找到 `WHY`、`MY SCOPE`、`WHAT CHANGED` 和 `EVIDENCE`
5. 只有真正改变职业弧线、责任边界或方法论的新工作，才值得增加阶段；新增项目本身不自动增加页面
6. 收尾回到长期方法、目标方向和适合承担的责任，不重复罗列项目

当前前两页应在一分钟内讲清完整职业弧线。默认优先替换较弱案例或更新证据，而不是持续增加 slide 数量。

## 讲稿与岗位材料

- 讲稿负责转场、取舍、因果和口头解释，不照读 slide 上的标签与数字
- 公开讲稿与私有讲稿共享同一条职业主线；核心事实变化时，两者在同一次维护中同步
- 私有讲稿可以增加时间紧可略段落、贡献边界、面试接法和未公开细节，但不反向污染公开版本
- 公司 brief 从通用材料选择两到三个最相关案例，说明匹配点、能力缺口和待确认问题
- 每轮面试产生的新岗位信息写入公司目录；只有能改变通用表达的事实或反馈，才回流到通用讲稿

## 更新流程

出现新角色、重要交付、已验证指标、贡献边界变化或定位调整时，按以下顺序维护：

1. **确认事实**：核对来源、日期、角色、贡献动词、指标口径和是否仍然成立
2. **确定边界**：标记为私有、可定向沟通或可公开；新的内部指标默认不公开，直到人工确认
3. **更新事实层**：内部任职和绩效事实先进入私有事实档案；公开项目事实回到对应项目证据
4. **更新 Resume**：判断它是否改变定位、四条工作主线或最近经历；不把所有新事实都塞进简历
5. **更新 Work Timeline**：判断它是现有阶段的新证据，还是足以改变职业弧线的新阶段
6. **同步讲稿**：更新公开和私有讲稿中的对应事实、转场与时间控制
7. **检查公司 brief**：仅更新确实受影响的岗位匹配材料，不批量复制通用内容
8. **生成派生产物**：按 `sites/miaodx.com/resume/README.md` 重新生成 PDF；不要手改 PDF
9. **完成验证**：执行下方检查；子模块改动均先在对应仓库提交、推送，再更新 LIP gitlink

## 何时更新

### 立即触发

- 任职、角色或责任范围变化
- 新结果达到稳定、可复查状态
- 现有数字、贡献归因或公开口径被纠正
- 项目从探索、仿真、真机验证或正式交付进入新阶段
- 求职方向变化，导致首页定位或案例排序需要调整

### 不自动触发

- 尚未验证的原型或一次性成功
- 只改变实现细节、不改变责任或结果的工具升级
- 无法解释统计口径的更大数字
- 与长期定位无关的短期任务

### 定期复查

- 每次正式投递或面试前：检查岗位定位、最近经历、链接和 PDF
- 每季度：检查项目状态、数字时效、命名、公开边界和跨材料一致性
- 每次重大阶段结束后：判断是否需要调整职业弧线，而不只是追加项目

## 一致性与公开边界

跨材料至少检查以下内容：

- 项目名使用固定写法，例如 `RoboClaws`、`RoboHarness`
- 日期可以按载体分别使用 `YYYY.MM` 或 `YYYY H1/H2`，但时间范围不能冲突
- 管理人数与跨团队影响范围分开表达
- 底层能力成功率、端到端任务成功率和平台级结果不能混用
- 内部项目与公开脱敏/重新实现版本要明确区分
- 团队平台、合作项目和个人主导项目使用不同贡献动词

公开材料不得包含：私有链接或 token、同事姓名、绩效评级、未经批准的内部版本号和客户信息、不能解释口径的指标、未经授权的工作照片或附件。私有仓库是访问边界，不代表内容可以自动公开。

## 验证清单

### 内容

- [ ] 每段主要经历都能回答叙事骨架中的关键问题
- [ ] Resume 的摘要、工作主线和经历没有大段重复
- [ ] Work Timeline 前两页能独立讲清职业弧线
- [ ] 数字有范围和口径，贡献动词准确
- [ ] 项目名、角色、日期和当前状态跨材料一致
- [ ] 公开材料通过单独的敏感信息检查

### Resume

- [ ] `resume-data.js` 同时驱动网页和打印版，没有平行文案源
- [ ] 网页在桌面和手机宽度无横向溢出或文本重叠
- [ ] PDF 已重新生成，文件名与 `pdfFile`、下载链接一致
- [ ] 当前目标为 A4 两页；若改变页数，先确认阅读收益，而不是被动溢出
- [ ] PDF 页面无截断、孤立标题或不合理跨页

具体生成方式以 `sites/miaodx.com/resume/README.md` 为准。

### Work Timeline

- [ ] 受影响 slide 已按 `1440x900` 和 `390x844` 浏览器检查
- [ ] 桌面分页、手机连续阅读、speaker notes 和链接正常

- [ ] `npm run build:all` 通过并正确发布到 `/LIP/share/work-timeline.html`

Standalone deck 的具体路径、标点和截图规则以 `docs/agents/standalone-decks.md` 为准。

## 完成标准

一次维护只有同时满足以下条件才算完成：

1. 新事实可追溯，贡献和指标口径准确
2. Resume 能让读者在 30 秒内获得清晰定位和代表证据
3. Work Timeline 前两页能解释职业弧线，后续案例能独立讨论
4. 各材料信息密度不同，但没有事实冲突、命名漂移或重复维护源
5. 公开边界经过人工确认，派生产物已生成，仓库门禁和视觉检查通过

人类 owner 负责最终定位选择和新增公开信息审批；Agent 可以整理、同步和验证，但不得因“保持完整”自行扩大披露范围。
