## 产品定义

这份文档从机器人学习的研究问题和公开工程生态出发，帮助已有工程背景的读者建立领域地图、理解方法之间的联系，并选出适合自己资源条件的仿真或离线实验。技术项目、论文、工具和公开实践构成主要叙事节点。

暂定标题：**机器人学习：技术地图、公开实践与仿真复现**。

它回答四个问题：

1. 示教、数据、策略、VLA/WAM、仿真和部署分别解决什么问题，怎样相互联系；
2. 经典工作与团队公开实践提出了什么方案，证据能支持哪些判断；
3. 基础库、模型、数据集和 benchmark 分别处于哪一层，应该怎样组合；
4. 哪些项目值得先读或先做，怎样用一个无真机闭环检查自己的理解。

自驾研发者也是读者，但已有能力怎样迁移、岗位怎样切入的主线交给方案 A 持续展开。本篇保留通用的执行接口和证据边界，不以自驾术语映射作为章节骨架。

作者自己的项目只作为边界案例和反例，不承担行业最佳实践的证明责任。正文中的“推荐”必须绑定任务条件、来源和验证方式；无法复跑的内容标为未验证。

## 读者与阅读路径

默认读者具有软件、数据、模型或系统工程背景，希望理解机器人学习与操作任务；不要求已经从事自驾研发，也不要求先掌握全部机器人基础。

| 阅读目标 | 先读什么 | 读完应交出的东西 |
| --- | --- | --- |
| 建立领域认识 | 技术地图与问题演进 | 能区分示教、策略、模型、工具和评测节点，并解释其联系 |
| 了解公开实践 | 团队卡、社区教程、技术报告与奖项入口 | 一份有来源和适用边界的阅读清单 |
| 开始模型实验 | ACT / Diffusion Policy，再按需进入 VLA/WAM | 固定任务、数据、checkpoint 和评测条件的实验记录 |
| 理解工程生态 | 仿真/控制工具与执行接口 | 一套职责明确的组件组合及无真机验证方案 |

需要从岗位和原有工程经验寻找切入点时，先读 [方案 A 的角色入口](autonomous-driving-to-robotics-rd-guide.md)。

每节统一采用：**公开证据 → 它实际证明了什么 → 不能证明什么 → 可迁移的工程问题 → 最小验证**。这样把博客、产品和论文放回证据边界中，而不是直接改写成最佳实践。

## 文档形态

采用“短正文 + 参考卡 + 证据台账 + 技术地图草案”，避免按十一个模块写成教材：

1. **技术地图与问题演进**：先定位示教、数据、策略、VLA/WAM 与工程支撑，再解释经典工作的联系。
2. **公开实践与阅读入口**：把团队卡、社区教程、报告和奖项放回具体问题，区分研究信号与可复现证据。
3. **工具与项目分层**：解释仿真、规划、数据、模型与评测的职责，以及观测/动作接口。
4. **无真机体验与最小闭环**：按资源和目标选一个 ACT/LeRobot 等候选任务，记录训练、运行、评测与失败。
5. **方法扩展与适配边界**：从经典策略到 VLA/WAM，说明换任务、本体、数据和部署条件需要重新验证什么。
6. **参考卡与证据台账**：保存原始来源、固定版本、许可、硬件、命令和复现状态；SVG 呈现已审阅的关系。

### 一、技术地图：研究问题如何展开

先用 Markdown 固定两张互补的地图：

- **领域全景图**：按技术分支组织节点，包括本体与示教接口（ALOHA、Mobile ALOHA、UMI、DROID）、控制与规划、操作策略（BC、ACT、Diffusion Policy）、数据与基准、通用机器人模型、语言与任务规划、仿真与数据基础设施、世界模型/WAM、系统与部署。项目可以同时出现在多个能力层；它回答“这个领域由哪些相互依赖的能力组成”。
- **VLA/WAM 演进图**：以“示教 → 数据 → 策略 → 通用策略/VLA → 世界模型/WAM”为阅读主干，把示教成本、action chunking、移动操作、手持采集、规模化数据，与 Transformer policy、跨本体数据、开放 VLA、flow/action model、视频/动作预训练放在一起。它回答“不同路线如何回应数据、动作和泛化问题”；这是并行路线的交汇，不是所有项目严格按年代走完同一阶梯。

**展示约定**：节点使用具体方法、模型、系统或工具名，公司单列为归属；DYNA-1 / DYNA-2 标注 `Dyna · 公司研究` 和“本轮未找到公开权重入口”，作为报告阅读入口。同一项目仅保留一张主卡，UMI、DROID 和 ALOHA/ACT 的跨层细节用贡献条与细线/圆点关联，细节继续留在证据台账。卡片只显示已确认的发表/开源年份；来源核对日期放入图脚和台账，不再使用“核对*”。

**本轮内容决策**：ALOHA 的平台贡献与 ACT 的策略贡献分开记；UMI 保留 SLAM、相对轨迹、时延匹配和跨平台部署；DROID 保留共同 Franka 平台上的多机构/场景数据贡献，不误写成跨本体数据集。WAM 是独立展示的探索分支：明确研究问题、DYNA-1/2、OpenWAM 模型实验与 CPU 契约的不同证明范围，部署另列为共用工程约束；研究影响力、工程入口价值、无真机复现价值分别判断。

每个节点先记录：时间、问题、代表论文/项目、直接继承关系、共享数据或 benchmark 关系、仿真入口、可复现等级和证据边界。SVG 只负责呈现这些已审阅的关系，不承担新的事实整理。社区文档、工程 Blog、技术报告和顶会奖项继续作为来源索引，不把它们写成全量综述。感知、Agent、部署、安全和完整评测体系先作为后续专题入口，不在第一版展开。

### 二、公开实践与资料怎样阅读

- 四张团队卡分别说明数据/模型、平台组合与部署问题，保留一手来源和公开边界。
- 社区教程用于找到操作入口；技术报告和顶会奖项用于筛选研究；Awesome 用于发现项目。
- 逐项说明“提出了方案”“开放了接口”“有可运行实验”“在固定条件下验证了效果”之间的差别。

### 三、从工具生态到可执行实验

- 区分 MuJoCo、Isaac Sim/Lab、cuRobo、MoveIt 2、LeRobot/openpi 的职责，按任务组合。
- 说明本体、观测/动作、坐标、频率、动作时效和 reset 等最小接口条件。
- 把规划器、策略模型、控制器和执行器放回各自位置；无需为了入门先安装整套工具。

### 四、最小 simulation-first 闭环

- 优先研究 ACT + MuJoCo Transfer Cube，或 LeRobot 的对应路线；cuRobo/MoveIt 仅在需要规划基线时接入。
- 固定任务、环境、机器人、控制周期、数据、seed 和版本，产出 rollout、成功数/总数和失败记录。
- 扩展到 Diffusion Policy、LIBERO 上的 VLA、UMI/DROID 离线数据与 WAM 分级体验；不混淆流程验证和模型效果。

### 五、从一个方法到新任务与新本体

- 对比经典策略、通用策略/VLA、WAM 的数据、动作表示、训练、推理和评测要求。
- 适配新任务前核对本体、schema、归一化、动作 horizon、时延和许可，再决定是否微调或更换组件。
- 自驾岗位分工、经验迁移和从需求到交付的主线由方案 A 展开；本篇保留通用实验判断。

## 最佳实践研究方法

最佳实践不是把搜索结果拼成行业共识。每张实践卡和工具条目先建立证据表，再写推荐结论：

| 字段 | 内容 |
| --- | --- |
| 工程问题 | 需要做什么决定 |
| 候选路线 | 主流方案、替代方案和不适用方案 |
| 推荐默认 | 在什么前提下优先采用 |
| 证据 | 支持推荐结论的摘录、结果或实现位置 |
| 失败模式 | 典型错误、适用边界和反例 |
| 验证方式 | 读者如何证明自己的实现满足条件 |
| 更新时间 | 资料和结论最后核对日期 |
| 来源定位 | 公开 URL、仓库提交/tag、模型/数据/环境版本或文档路径 |
| 证据等级 | 设计提案、官方说明、原始论文、可复现实验或维护中的实现 |

研究顺序：先查标准、官方文档和原始项目，再看论文和成熟实现，最后使用社区文章补充背景。对快速变化的模型、数据格式和仿真工具记录版本；对系统基础和控制概念保持稳定表述。

第一版以 2026 年当前公开资料为时间边界，按实践卡和工具条目记录更新时间。不追求覆盖全部具身智能论文或公司，也不把个人项目当前采用的路线直接称为最佳实践。

第一版至少复现一个 simulation-first 基线。证据表记录公开提交或版本、模型/数据/环境身份、运行命令、seed、预期产物或指标、硬件依赖和最近一次复跑日期；无法复跑的内容标为未验证，不写成已复现结果。外部实践卡只纳入可定位到官方页面、论文、仓库或产品文档的材料。

证据台账先放在 [`autonomous-driving-to-robotics-guide-evidence.md`](autonomous-driving-to-robotics-guide-evidence.md)，正文只引用已经过来源和边界检查的条目。
