## 产品定义

暂定标题：**从自驾到具身智能：系统、模型与真实世界实践指南**。

这是一份面向自驾从业者的具身智能领域指南。它帮助读者在当前公开最佳实践的基础上，快速建立共同语言、找到自己的技术入口、复现一个可信基线，并逐步参与真实机器人任务。

文档的中心不是讲述作者如何完成转型，而是回答四个问题：

1. 具身智能系统由哪些模块组成，各模块当前通常怎样做；
2. 自驾经验在哪些地方可以直接迁移，在哪些地方必须改造；
3. 不同背景的自驾工程师应从哪里切入；
4. 如何用仿真、真机、数据和证据判断一个结果是否可信。

我们的工作经验只作为案例、旁注、反例和实践证据。它不承担全文叙事主线，也不代表行业共识。

## 读者与阅读路径

默认读者已经理解软件工程、传感器、模型训练、系统集成或量产研发中的至少一部分，不默认掌握机器人动作语义、运动学、接触和真机执行。

按背景提供入口：

| 读者背景 | 首选模块 | 重点补齐 |
| --- | --- | --- |
| 感知工程师 | 感知、状态估计、坐标与标定 | 本体、操作对象、时空同步 |
| 规划/控制工程师 | 运动规划、控制、动作执行 | 学习策略、动作 chunk、任务语义 |
| 数据工程师 | 数据采集、数据契约、训练闭环 | 机器人状态、示教、动作可执行性 |
| 模型工程师 | VLA/VLN、后训练、部署 | 控制周期、接口契约、真机失败 |
| 测试/评测工程师 | 仿真、评测、验收和失败归因 | 任务成功定义、物理复位、sim-to-real |
| 平台/系统工程师 | 运行时、部署、观测和安全 | 多频率执行、控制边界、本体差异 |

每个模块都采用统一入口：**问题是什么 → 当前常见方案 → 推荐默认实践 → 替代路线及适用条件 → 常见失败 → 如何验证 → 自驾经验如何迁移 → 进一步阅读**。

## 核心目录

### 〇. 具身智能全局地图

回答“具身智能系统到底在解决什么问题”。

- 从任务和环境出发定义具身智能，而不是从某个模型名词出发。
- 说明本体、传感器、状态估计、感知、任务规划、运动规划、策略、控制、执行器和反馈的关系。
- 对照移动机器人、机械臂、移动操作和人形机器人，说明哪些模块共享、哪些约束不同。
- 解释 VLM、VLN、VLA、模仿学习、强化学习和 WBC 的职责边界。
- 给出“任务意图 → 规划/策略 → 动作适配 → 控制器 → 执行器 → 观测反馈”的共同骨架。

产物：一张系统地图、一张模块关系图、一张自驾术语到机器人术语的映射表。

### 一. 机器人本体、传感器与执行链

回答“机器人为什么比车辆更容易在接口层失败”。

- 机器人本体、关节、末端执行器、底盘和工具的能力边界。
- 相机、深度相机、力/扭矩、编码器、IMU 等传感器及其时空关系。
- 坐标系、TF、标定、单位、关节顺序、姿态表示和状态估计。
- 观测、命令、动作、控制器接收和实际施加的区别。
- 控制频率、传感器频率、推理频率、动作 chunk 和 deadline。
- 急停、超时、动作过期、降级和复位的基本边界。

推荐实践应优先以明确的接口契约、时间戳和来源追踪为默认，而不是先追求统一万能抽象。

自驾经验入口：车辆传感器同步、板端时延和资源预算可以迁移；车辆状态到关节/末端动作的语义必须重新确认。

### 二. 感知、状态估计与空间理解

回答“机器人需要理解什么，和车辆感知有何不同”。

- 从场景感知扩展到可操作物体、接触面、可达空间、遮挡和人的状态。
- 目标检测、分割、姿态、深度、跟踪、三维重建和场景图的适用边界。
- 状态估计、定位、地图和动态对象跟踪的组合方式。
- 开放词汇感知、视觉语言模型和结构化几何表示的关系。
- 数据标注、伪标签、多模型复核和人工异常处理。
- 视觉上“看到了”与任务上“可以执行”之间的差距。

最佳实践部分需要比较几何方法、端到端方法和 VLM 辅助方法，不把某一条路线写成默认答案。

### 三. 任务规划、运动规划与控制

回答“从一句任务指令到机器人动作，中间有哪些层”。

- 任务规划、行为规划、运动规划、逆运动学、轨迹生成和低层控制的分层。
- 导航、抓取、放置、双臂协同和移动操作的典型链路。
- 绝对位姿、固定锚点相对位姿、逐步增量、关节空间和末端空间动作。
- 经典规划、学习策略、混合式系统和 WBC 的使用条件。
- 接触、摩擦、碰撞、可达性、稳定性和安全约束。
- 为什么一个动作能力成功率不能直接代表完整任务成功率。

自驾经验入口：规划约束、轨迹质量、控制稳定性和故障分层可以迁移；道路拓扑和车辆运动假设不能直接套用到操作任务。

### 四. 数据：从采集事实到训练产品

回答“机器人数据为什么不能只看成视频加标签”。

- 示教、遥操作、真实采集、仿真合成和失败轨迹的来源。
- episode、trajectory、frame、observation、action 和 event 的语义。
- 异步流、时钟域、有效区间、坐标变换、动作表示和本体描述。
- measured、estimated、commanded、executed、retargeted 和 simulated 的区分。
- 数据质量、缺失、遮挡、同步误差、标定版本、数据泄漏和训练/评测拆分。
- 数据转换、交付契约、血缘、损失报告和目标训练程序的可读性。

推荐默认实践是先保留源事实、显式声明解释和派生，再生成面向训练的物理视图。RoboData 的 RDIR/RDX 设计可作为数据语义的讨论材料，但必须标明其当前是设计阶段。

### 五. VLA/VLN、策略模型与后训练

回答“当前具身模型怎样进入真实任务”。

- VLM、VLN、VLA、行为克隆、扩散策略、世界模型和强化学习各自解决什么问题。
- 预训练模型、任务适配、监督微调、LoRA、全量微调、数据混合和动作 tokenizer。
- observation/action schema、归一化、历史窗口、动作 horizon、chunk 执行与重规划。
- 云端推理、板端推理和分层部署的延迟、成本、可靠性与隐私权衡。
- 从公开基线到自有本体和自有场景的适配检查清单。
- 如何区分模型复现、训练可运行、策略在仿真有效和真机任务成功。

推荐实践以固定基线、明确数据和模型 lineage、冻结评测条件、记录部署延迟为前提；不根据单次真机演示宣称通用能力。

### 六. 仿真、SIL/HIL 与 Sim-to-Real

回答“仿真到底证明了什么”。

- lockstep、wall-paced、SIL、HIL 和 physical robot 的区别。
- 任务、资产、控制器、传感器、随机种子、初始状态和执行时序的身份。
- 物理步长、控制周期、decimation、推理等待和队列行为。
- 接触、动力学、渲染、延迟、噪声和本体差异带来的 sim-to-real 风险。
- 同一策略跨 MuJoCo、Isaac、Genesis 等环境时，哪些语义可以比较、哪些不能比较。
- 仿真数据生产、基线复现和迁移实验的证据要求。

RoboForge、crossrun 和 Soma 的材料可用于说明执行语义和实验边界；设计文档与已验证结果分开标识。

### 七. 评测、验收与失败归因

回答“一个机器人任务什么时候算完成”。

- 能力评测、任务评测、系统评测、部署评测和安全评测的分层。
- 成功率、SR、NE、碰撞、接触、轨迹质量、时延、资源占用和恢复行为。
- 任务成功、动作成功、运行完成、证据完整和人工批准的区别。
- 基线、固定种子、holdout、回归、趋势、置信区间和失败样本。
- 失败归因：数据、模型、坐标/动作适配、环境、控制器、基础设施和评测器。
- 机器生成报告、视觉证据、状态轨迹、告警和人工复核的组合。

推荐默认实践是先定义完成条件和失败边界，再运行策略；不能让“进程返回成功”代替任务验收。

RoboHarness 和 RoboClaws 的公开材料可作为证据包与验收边界案例，但单次基线或无结论对照不升级为行业结论。

### 八. 真机部署、运行时与安全边界

回答“模型如何变成可持续运行的机器人能力”。

- 部署拓扑、设备资源、推理服务、机器人 SDK、ROS 2 和控制器边界。
- 输入输出 schema、能力发现、超时、deadline、动作过期、重试和 reset epoch。
- 运行监控、日志、trace、回放、版本和现场问题复现。
- 仿真、实验室、受控场景、小批量和开放环境的发布闸门。
- 人工接管、保护停机、恢复和物理风险的责任边界。
- 什么时候应使用平台化能力，什么时候先保留一个窄任务、可审计的 vertical slice。

RoboWBC、RoboArc 和 Soma 提供运行时契约、能力编排和时序边界的具体材料；各项目的验证范围必须单独说明。

### 九. Agent、Skill 与开放任务

回答“为什么开放任务需要新的软件分层”。

- 固定 Workflow、任务规划 Agent、Skill、Tool、MCP 和机器人后端的边界。
- Agent 的目标理解和规划，与机器人执行权限和安全策略的分离。
- 能力描述、参数校验、状态反馈、取消、超时和失败恢复。
- 开放目标、导航、抓取、整理和多步骤任务的评测难点。
- VLM 作为任务生成器、被测策略、标注器或测试操作员时的不同风险。
- 什么时候应回到固定流程或人工复核。

RoboClaws、RoboArc 和 Endless Testing 经验作为案例，不把当前 Agent 框架写成通用机器人架构标准。

### 十. 从自驾经验进入机器人项目

这一章不再是个人转型故事，而是角色化的切入指南。

| 切入方向 | 第一类问题 | 建议先交出的产物 |
| --- | --- | --- |
| 系统/平台 | 链路、资源、时序和故障是否可观察 | 执行链路图、接口契约、时序和资源报告 |
| 感知/定位 | 观测是否足以支持任务和动作 | 坐标/标定说明、场景数据和失败样本 |
| 规划/控制 | 动作是否可达、稳定、及时和安全 | 动作语义、控制边界、仿真与真机对照 |
| 数据 | 数据是否可解释、可转换、可复现 | 数据卡、血缘、质量报告和训练/评测拆分 |
| 模型 | 模型改动是否在固定条件下带来改善 | checkpoint lineage、评测报告和部署延迟 |
| 评测 | 结果是否真的代表任务完成 | 合同、基线、证据包、失败归因和回归报告 |

不设统一天数或月份。每个入口用前置条件、实践任务、可验证产物和停止条件描述“快速切入”。

## 最佳实践研究方法

最佳实践不是把搜索结果拼成行业共识。每个模块先建立证据表，再写推荐结论：

| 字段 | 内容 |
| --- | --- |
| 工程问题 | 需要做什么决定 |
| 候选路线 | 主流方案、替代方案和不适用方案 |
| 推荐默认 | 在什么前提下优先采用 |
| 证据 | 官方文档、原始论文、可复现实验或维护中的开源项目 |
| 失败模式 | 典型错误、适用边界和反例 |
| 验证方式 | 读者如何证明自己的实现满足条件 |
| 更新时间 | 资料和结论最后核对日期 |

研究顺序：先查标准、官方文档和原始项目，再看论文和成熟实现，最后使用社区文章补充背景。对快速变化的模型、数据格式和仿真工具记录版本；对系统基础和控制概念保持稳定表述。

第一版以 2026 年当前公开资料为时间边界，模块级记录更新时间。不追求覆盖全部具身智能论文，也不把个人项目当前采用的路线直接称为最佳实践。

## 真实经验的使用方式

### 工厂任务交付

说明整机集成、性能、测试和完整任务验收如何连接。公开口径包括 90+ 项专项测试、整机 CPU P90 低于 60%、稳定后每类工站 300+ 组端到端自测，以及所负责任务平均时长由 3.5 分钟降至 2 分钟以内。只用于解释系统交付和验收，不作为通用机器人性能基准。

### VLN 数据、部署与评测

说明部署约束如何影响数据生产、批量评测和动作输出表示。明确模型架构与训练由模型同事主责，本文只把部署、数据和评测经验作为跨模块协作案例。

### π0.5 公开基线到 G2

说明固定上游身份、核对数据和 action/observation 契约、完成场景适配与真机链路的过程。只证明两组具体任务的工程链路，不扩写成基础模型原创、通用操作能力或稳定成功率。

### Soma 时间尺度复盘

使用公开报告说明：2 ms 物理步与 20 ms 控制周期没有按十个子步推进，会让仿真时间慢十倍。这个案例用于说明先验证时钟、频率和 decimation，再比较控制效果。

### RoboClaws 与 RoboHarness

使用公开证据说明开放任务执行与机器验收的边界。RoboClaws 的一次对照实验中，运行结果成功不等于语义验收通过；RoboHarness 则展示如何把阶段指标、告警、基线和视觉证据组成 proof pack。它们是方法案例，不是整个领域的效果结论。

## 写作顺序

1. 建立最佳实践证据表，先覆盖系统骨架、数据、模型、仿真和评测五个核心模块。
2. 起草总览页和角色入口，确认读者能从自身背景找到起点。
3. 起草核心正文，优先写任务定义、执行链、数据到真机的闭环。
4. 补模型、仿真、评测、部署和 Agent 专题。
5. 把真实经历压缩成案例卡和反例，不让案例重新占据正文主线。
6. 补术语、工具、资料索引和更新时间。
7. 做技术事实、公开边界、模块完整性和链接检查，再决定是否拆分页面。

## 完成标准

- 总览和目录能让不同背景的自驾读者找到自己的模块入口。
- 每个核心模块都包含当前常见方案、推荐默认实践、替代路线、失败模式和验证方式。
- 推荐结论有公开来源、适用条件和更新时间；个人经验与行业实践明确区分。
- 至少三个真实案例用于解释实践边界，其中包含 Soma 时间尺度和 RoboClaws 验收差异两个反例。
- 能区分运行成功、动作成功、任务成功、真机链路打通和稳定交付。
- 不设置固定天数学习计划；实践路径以能力、产物和停止条件定义快速切入。
- 正文不包含内部人员、服务地址、访问 token、私有材料链接或定向披露事实。
- 初稿完成后更新 `drafts/index.md`；正式发布前更新 `site-map.mjs` 并运行 `npm run build:all`。
