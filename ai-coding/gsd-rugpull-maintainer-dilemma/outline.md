# 大纲与决策记录

> 这份文件记录文章构思过程中的关键决策，方便后续 review 时回顾"为什么这么写"。

## 核心论点（一句话）

GSD 跑路不是个人道德问题，是 AI coding 时代独立开源维护者**结构性两难**的极端样本——当大厂在 6 个月内吸收掉你的"创新"时，独立维护者没有体面的退路。

## 4 种结局（视角一的高潮）

按"被收编程度"递减排列：

| 人物 | 项目 | 结局 | 时间 |
|------|------|------|------|
| Den Delimarsky | GitHub Spec Kit（61K+ stars） | 从 Microsoft 跳槽到 Anthropic | 2026-01-11 |
| Peter Steinberger | OpenClaw（200K+ stars） | 独立创业 → 加入 OpenAI | 2026-02-15 |
| Paul Gauthier | Aider（44K+ stars） | 沉默退场，社区 fork 接盘 | 2025-08 后 |
| Lex Christopherson | GSD（60K+ stars） | 卷币跑路 | 2026-05-22 |

**为什么这 4 个并列：** 都是 AI coding 周边明星项目的独立维护者（或大厂内部 OSS lead），都面对 Anthropic / OpenAI 的"借鉴 + 收紧"压力，最后走向了 4 种完全不同的结局——证明这不是个人选择问题，是结构性现象。

## 关键决策（讨论过程）

### Q：v2 故事要不要重点讲？
**最终：弱化处理。** 第一版考虑用 v2 + Anthropic 4/4 政策作为视角一的核心论据，但用户判断 v2 被卡只是"压死骆驼最后一根稻草"，不是主因。最终 v2 故事压到 100 字左右，作为"v1 被吸收 → v2 也走不通"的补充叙事。

### Q：4/1 失联和 4/4 政策的时间巧合，要不要明说？
**最终：暗示，不明说。** 这两个时间点很难是巧合，但对一个没出来辩护的人做归因不合适。文章里只列时间点，让读者自己看出来。

### Q：roboharness 等自己项目要不要 plug？
**最终：完全删除。** 这篇文章不是借势宣传我们的工具。所有自我推广段落（包括"给未来作者的建议"里的反例）都去掉。

### Q：标题要不要更尖锐？
**最终：保留"60K Star 和 50 万美金，怎么选？"** 这是讨论中用户最初给的方向。算账感是好钩子，问号让读者带着问题进来。备选过的更尖锐版本（"AI 大厂正在杀死独立开源维护者吗？"、"为什么 GSD 一定会跑——AI 大厂时代独立维护者的死局"）都被否决。

### Q：写多长？
**最终：2400-2600 字。** 不是大纲列出所有 repo（那是另一种文章），而是用 3-4 个对照案例支撑核心论点。

### Q：建议要不要加第 4 条"别在大厂下一层做 wrapper"？
**最终：不加。** 太武断，会显得在劝退所有 AI coding 开源项目。事实上很多 wrapper 类项目活得很好（Cline 融了 $32M，Continue 融了 $5.1M）。文章不想给出绝对禁令。

## 文章里有意识地保留的张力

- **承认告别信里有真话**（被吸收是事实）但同时**不为 Lex 洗地**（卷币跑路是错的）
- **同情独立维护者困境**但**对结构性问题持悲观态度**
- **赞扬 trek-e**但**质疑这种"雷锋模式"的可持续性**
- **建议接受 commoditization**但**坦承这要求个人有承受焦虑的能力**

这些张力让文章不像 hot take，更像一次结构性思考。
